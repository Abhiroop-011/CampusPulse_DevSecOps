Phase 3 - Containers

🐳 Docker - Multi-Stage, Non-Root

⚙️

Backend - FastAPI

Multi-stage build. Runtime is python:3.12-slim, runs as UID 10001. No shell, no root access.

🌐

Frontend - React to Nginx

Node 22 builds the Vite bundle. Final image is nginx:1.27-alpine serving static files only.

🗄️

Database - PostgreSQL 16

Official postgres:16-alpine with env-var seeded credentials and persistent data volume.

Phase 5 - Security

🛡️ Security at Every Layer

🔍

Aqua Trivy CVE Scanning

Scans Docker images in CI before the registry push. Blocks any CRITICAL or HIGH CVE not explicitly documented and triaged.

0 Critical0 High (unmitigated)
🚫

Non-Root Containers

Backend runs as UID 10001. Frontend as the nginx user. No container process ever runs as root.

🔐

Zero Secret Leakage

All .env, .tfstate, and *.pem files blocked via .gitignore. Git history is completely clean of credentials.

🏗️

AWS Cloud Hardening

KMS envelope encryption for Kubernetes secrets and IMDSv2 mandatory tokens to block SSRF credential theft attacks.

Phase 6 - Orchestration

☸️ Kubernetes and Helm - Declarative Deployment

Phase 10 - GitOps

🔄 Argo CD - GitOps Continuous Delivery

Argo CD watches Git. When Helm charts change, it automatically syncs the cluster to match. No manual kubectl needed.

  • 📁Declarative application YAML in gitops/argocd-app.yaml
  • 🔗Points Argo CD at helm/campuspulse/ chart path
  • 🔁Auto-sync enabled - cluster self-heals drift
  • 🔔Manual cluster changes get automatically reverted
  • 📦Syncs to campuspulse namespace on AWS EKS
💡

Why GitOps?

Git is the single source of truth for what runs in production. Full audit trail. Zero config drift possible.

🔐

Access Control

Only Argo CD modifies cluster state. Developers push to Git, not to Kubernetes directly. Eliminates a whole class of human errors.
